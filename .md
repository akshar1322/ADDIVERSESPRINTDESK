# AI Agent Master Plan --- 3D Printing Workflow Management System

## Project Mission

Transform the existing **AddiVerse Print Desk** web application into a
production-ready **3D printing workflow management system** with two
primary experiences:

1.  **Admin Portal** --- authenticated management system for admins.
2.  **Employee Portal** --- no traditional email/password login page;
    employees verify their identity and shift before accessing work.

The system must preserve useful parts of the existing codebase and
database. Do **not** blindly rebuild the application from scratch.

------------------------------------------------------------------------

# AI Agent Operating Instructions

You are the senior full-stack engineer responsible for analyzing,
planning, implementing, testing, and documenting this upgrade.

## Core Rules

-   First inspect the entire existing codebase.
-   Understand the current architecture before modifying files.
-   Reuse stable existing components, models, utilities, styles, and
    APIs.
-   Do not remove existing features unless they conflict with the new
    requirements.
-   Do not make large destructive changes without documenting why.
-   Keep the application deployable after every major phase.
-   Use TypeScript strictly.
-   Do not use `any` unless absolutely unavoidable.
-   Keep server-only secrets and database operations off the client.
-   Validate all server inputs.
-   Add proper loading, empty, success, and error states.
-   Preserve database history. Completed jobs must never be
    automatically deleted.
-   Track important actions with timestamps and actor identity.
-   Before coding each phase, inspect the relevant files and create a
    short implementation checklist.
-   After coding each phase, run lint, type-check, build, and relevant
    tests.
-   Fix all introduced errors before continuing.
-   Never expose secrets in source code or logs.

# Workflow State Machine

Use explicit server-controlled job statuses.

``` text
NEW
  ↓
IN_PROGRESS
  ↓
READY_TO_DELIVER
  ↓
DISPATCHED
  ↓
ARCHIVED
```

Optional additional statuses only if justified:

``` text
ON_HOLD
CANCELLED
```

Rules:

-   Only valid state transitions are allowed.
-   State transitions must happen on the server.
-   Every transition creates an activity log.
-   Do not trust status values sent directly from the browser.
-   Dispatched jobs remain visible to employees for 24 hours.
-   After 24 hours, hide them from the employee workspace.
-   Never delete them automatically.
-   Admins can always search and view historical jobs.

# In Progress Tab

Show active production jobs.

Employees can update only operational fields:

-   Total quantity printed
-   Remaining quantity
-   Printer assignment
-   Printer number/machine identifier
-   Material used
-   Material unit
-   Progress notes

Prefer this rule:

``` text
remainingQuantity = requiredQuantity - printedQuantity
```

Do not allow employees to manually create inconsistent remaining
quantities.

Validation:

-   Printed quantity cannot be negative.
-   Printed quantity should not exceed required quantity unless admin
    policy explicitly allows overproduction.
-   Material usage cannot be negative.
-   Material unit must be normalized.
-   Store a canonical value in grams when possible.

Display:

-   Required quantity
-   Printed quantity
-   Remaining quantity
-   Progress percentage
-   Printer
-   Material used
-   Started by
-   Current/last employee
-   Started at
-   Current shift
-   Last updated at

Every meaningful update creates an audit/activity event.

# Ready to Deliver Transition

When printing is complete, employee selects:

`Ready to Deliver`

Before transition:

1.  Require at least one completed-work photo.
2.  Validate completion data.
3.  Upload and store photos.
4.  Save photo metadata.
5.  Prepare client communication.
6.  Open WhatsApp flow.
7.  Ask employee to confirm client notification.
8.  Transition job to `READY_TO_DELIVER`.

## WhatsApp Requirement

The admin stores the client's WhatsApp number.

The system should prepare a message containing:

-   Client name
-   Job name
-   Completion notice
-   Optional job reference

Important technical rule:

A normal web application should not pretend it can silently attach a
local photo and automatically press Send in WhatsApp Web.

Implement one of these approaches:

### Phase 1 --- Web Handoff

-   Upload completion photos to the application.
-   Generate a prepared WhatsApp message.
-   Open the correct client chat.
-   Employee manually attaches/sends the photo if required.
-   Employee confirms notification.

### Future Phase --- Official Business Messaging API

Design the code so an official WhatsApp business messaging provider can
be integrated later for automated approved messaging/media workflows.

Do not implement browser automation or unsafe WhatsApp Web scraping.

# Database Migration Strategy

Because the existing database already contains production-like models
and data:

1.  Inspect current Prisma schema.
2.  Map existing models to the new architecture.
3.  Create `docs/DATABASE_MIGRATION_PLAN.md`.
4.  Identify destructive changes.
5.  Prefer additive migrations first.
6.  Backfill data where necessary.
7.  Keep old columns temporarily if needed.
8.  Test migration against a safe database copy.
9.  Never run destructive production migration automatically.
10. Provide rollback notes.

Do not use `prisma db pull` as a substitute for a controlled application
migration strategy.

# Security Requirements

-   Admin pages require authenticated admin sessions.
-   Employee pages require active verified employee sessions.
-   Protect API routes independently from UI route protection.
-   Hash employee PINs.
-   Rate-limit employee PIN attempts.
-   Expire employee sessions.
-   Validate uploaded file types and sizes.
-   Use signed/private file URLs where appropriate.
-   Never trust client-provided actor IDs.
-   Never trust client-provided role values.
-   Never expose database credentials.
-   Never expose storage secrets.
-   Sanitize file names.
-   Log security-relevant actions.
-   Prevent unauthorized direct object access to job files.
-   Validate WhatsApp phone number format.
-   Use server-generated timestamps.
